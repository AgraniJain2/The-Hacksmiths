+-------------------------------------------------------------+
|                      1. Setup & Auth                          |
|  - Everyone (recruiters/interviewers/candidates) logs in      |
|    via Google OAuth (RBAC by role) -- finalized, single       |
|    auth method, no email/password or SSO alternative          |
|  - Connect Google Calendar / Gmail permissions                |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|              2. Create Interview Request                      |
|  - Recruiter defines: Interview Type (e.g. TECHNICAL_ROUND_1) |
|  - Required Skills (e.g. ["React", "System Design"])          |
|  - Required Seniority (e.g. SENIOR)                            |
|  - Number of panelists required (N)                            |
|  - Duration, buffer time (e.g. 15m)                            |
|  - Add candidate details (Email, Time zone)                   |
|  - NOTE: no named panelist -- all N seats are filled           |
|    automatically in step 6                                     |
|  - (Optional) Hiring manager named explicitly, not pooled     |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|         2B. Interviewer Pool Profile (parallel/ongoing)        |
|  - Each interviewer declares: skills, seniority level,         |
|    qualified interview types, active/inactive toggle          |
|  - Each interviewer declares: timezone + working hours         |
|    (default 09:00-18:00 in their own timezone)                 |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|         3. Candidate Availability Collection                  |
|  - Generate unique signed invitation link                     |
|  - Candidate logs in via the link, submits free time windows  |
|    in their own time zone                                      |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|         4. Interviewer Pool Feasibility Check                  |
|  - Filter pool by skills + seniority + interview type + active|
|  - Fetch Free/Busy via Calendar API for eligible interviewers  |
|  - For each candidate window, keep only interviewers who are: |
|      (a) calendar-free                                         |
|      (b) within THEIR configured working hours (own timezone) |
|      (c) buffer-respecting around adjacent events               |
|  - Keep candidate windows with >= N interviewers passing        |
|    all three checks (binary feasibility; ranking happens        |
|    later once a time is fixed)                                  |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|         5. Candidate Slot Selection                            |
|  - Candidate views feasible slots in their local time zone     |
|    and picks exactly one                                        |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|      6. N-Seat Interviewer Assignment                           |
|  - Recompute eligible+feasible interviewers live for the       |
|    fixed chosen time (same 3 checks as step 4)                 |
|  - Rank them:                                                  |
|      1) lowest rolling 7-day confirmed interview count          |
|         (burnout prevention / load balancing)                   |
|      2) tie-break: least recently assigned (round-robin)        |
|  - Offer to the TOP N in PARALLEL -- one offer per open seat,   |
|    to N distinct people (no broadcast to the whole pool)        |
|  - Each seat tracked independently:                              |
|      [Accepted]  ---> that seat is filled                       |
|      [Declined / no response before timeout] --->                |
|            re-rank remaining pool for THAT SEAT ONLY,            |
|            offer to next person, repeat                          |
|      [Pool exhausted for a seat] ---> escalate to recruiter /     |
|            ask candidate to re-pick a slot                        |
|  - Once all N seats are Accepted --> proceed to step 7            |
|  - Lock: reserve the target interviewer's profile row at the     |
|    moment each offer is created, so no one person gets double-   |
|    booked across two different interviews' overlapping times     |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|            7. Event Creation & Dispatch                        |
|  - Generate Google Meet link via Calendar API                  |
|    (conferenceData on the same events.insert call)              |
|  - Create ONE calendar event for candidate + hiring manager     |
|    (if any) + all N confirmed interviewers                      |
|  - Send confirmation emails with .ics calendar invites          |
+------------------------------+------------------------------+
                               |
                               v
+-------------------------------------------------------------+
|            8. Post-Booking & Exception Handling                 |
|  - Scheduled job sends reminders before the interview           |
|  - Candidate cancels/reschedules:                                |
|       -> release ALL N confirmed interviewer seats, notify      |
|          them, restart from step 3 with new availability        |
|  - ANY ONE confirmed interviewer cancels (after accepting):       |
|       -> release just THAT ONE seat, re-run step 6's ranking/   |
|          cascade for that seat only, same fixed time,            |
|          excluding them; candidate's confirmed time and the      |
|          other confirmed interviewers are untouched unless the   |
|          pool is exhausted for that seat (same escalation as     |
|          step 6)                                                  |
+-------------------------------------------------------------+

  - Single auth method (Google OAuth) only, despite the brief mentioning
    multiple auth options.
